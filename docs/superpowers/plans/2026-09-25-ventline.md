# Ventline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Ventline as a playable, server-authoritative, endless one-button score chase with solo runs, live races, powerups, rival silhouettes, a rolling map, and a persistent shared high-score board.

**Architecture:** `server/ventline.js` owns deterministic shutters, fixed-step flight, effects, round state, and snapshots. `server/ventline-server.js` owns WebSocket connections, independent solo runs, the live lobby, and one board writer. `src/pages/Ventline.jsx` renders snapshots and sends press-edge intent; it never simulates flight or scores.

**Tech Stack:** React 19, Vite 8, Canvas 2D, Node ESM, `ws` 8, Node's built-in test runner, Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-09-25-ventline-design.md`

## Global Constraints

- Server-authoritative movement, collision, pickups, score, and winner. No client prediction or client score payloads.
- Solo and live use the same endless shutter generator and scoring. Typical ordinary attempts target 30–90 seconds; no forced time limit.
- Service clear = 1 point; charged clear = 2. Pickup shutters are 5, 12, 19, and every seventh thereafter. Service grants one shield; charged grants one score charge. A prior charge adds 2 to the next clean clear. Shielded shutter passage scores zero and grants nothing. Floor and ceiling remain fatal.
- Live has 2–8 active players on one layout, no player collision or attacks. Solo and live results share `board-ventline.json`; only live wins enter the wins count.
- Port `8089`, path `/ventline-ws`, subprotocol `ventline.v1`, fixed 16 ms simulation step, `maxPayload: 4096`, `perMessageDeflate: false`, plain `ws://` JSON. The path must not start with `/ws`.
- Use `Object.hasOwn` for untrusted object keys, bound names before character processing, and retain leaderboard rows as arrays.
- Read raw `:root` color variables for canvas drawing. Use shape or text as well as color for routes, pickups, and player slots. Marketing copy avoids em dashes.
- On Windows, prepend `C:\Program Files\nodejs` to `PATH` if needed and invoke `npm.cmd`; do not change `server/package.json`.

The pure module exports `TICK_MS`, `gateAt(seed, index)`, `makeRun({seed,id,name,slot})`, `flap(run)`, `stepRun(run)`, `makeMatch(seed)`, `joinMatch(match,{id,name,slot})`, `setReady(match,id)`, `disconnectMatch(match,id)`, `stepMatch(match)`, `matchResults(match)`, `snapshot(match,viewerId,board,personalBest)`, and `soloSnapshot(run,board,personalBest)`. One `stepRun` or `stepMatch` call advances exactly 16 ms. `gateAt` takes a one-based shutter index. `makeRun` and `makeMatch` create new state; step functions mutate only that state and use no clock, socket, or I/O.

Client messages are `{t:'join',mode:'solo'|'live',name}`, `{t:'ready'}`, `{t:'flap'}`, and `{t:'retry',mode?:'solo'|'live'}`. The server answers `{t:'welcome',id,mode,slot}` and `snap` frames. A snapshot has `t:'snap'`, `phase`, `viewedId`, `personalBest`, `players` (`id,name,slot,x,y,alive,spectating,connected,score,clean,shield,charge,event:{seq,type}`), `gates` (world x, width, both opening bounds, pickup flag), and `board`; `soloSnapshot` uses the same presentation shape with one player. `event.type` is one of `shield-pickup`, `charge-pickup`, `shield-use`, or `charge-use`, and `seq` rises on each such event for reliable one-time effects. A completed run has a stable object identity and `banked` flag, so retry, disconnect, and repeated result ticks cannot bank it twice.

- [ ] **Step 3: Implement deterministic gates.** Use a local integer hash of `(seed,index)` so the course needs no infinite array. Use a fixed bounded speed schedule from 170 to 210 units/s, service width from 190 to 160, and charged width from 98 to 80. Keep both gaps separate and inside the shaft. Use the exact pickup rule:

```js
export const TICK_MS = 16
export const pickupAt = (index) => index >= 5 && (index - 5) % 7 === 0
const hash = (seed, index) => {
  let x = (seed ^ Math.imul(index, 0x9e3779b9)) >>> 0
  x = Math.imul(x ^ (x >>> 16), 0x7feb352d)
  x = Math.imul(x ^ (x >>> 15), 0x846ca68b)
  return (x ^ (x >>> 16)) >>> 0
}
const gap = (y, width) => ({ lo: y - width / 2, hi: y + width / 2 })
const serviceWidth = (index) => 190 - Math.min(30, index - 1)
const chargedWidth = (index) => 98 - Math.min(18, (index - 1) * 0.6)
export const speedFor = (index) => 170 + Math.min(40, index - 1)
export const gateAt = (seed, index) => {
  const topService = (hash(seed, index) & 1) === 0
  const offset = (hash(seed ^ 0x9e3779b9, index) % 41) - 20
  const serviceY = (topService ? 190 : 410) + offset
  const chargedY = (topService ? 410 : 190) - offset
  return { index, x: 480 + (index - 1) * 360, w: 28,
    service: gap(serviceY, serviceWidth(index)),
    charged: gap(chargedY, chargedWidth(index)), pickup: pickupAt(index) }
}
```
